# 한낮의 팝 도시로 디자인 바꾸기 설계

작성일 2026-09-28

## 개요

지금 화면은 "밤의 터널" 네온 사이버 스타일이다. 이것을 **한낮의 팝 도시**(원조 서브웨이 서퍼 느낌)로 바꾼다.
3D 게임 세상과 메뉴 화면을 한 분위기로 함께 바꾼다.

**쓰는 곳**: 행사·부스. 밝은 조명 아래 큰 화면을 여러 사람이 돌아가며 하고, 구경꾼도 본다.
그래서 멀리서도 또렷하게 보여야 하고, 처음 보는 사람도 장애물 뜻을 바로 읽을 수 있어야 한다.

**바꾸는 것은 겉모습뿐이다.** 스폰 규칙, 충돌 판정, 속도, 점수, 포즈 인식, 키보드, 화면 순서와 문구,
랭킹, 관리자 페이지는 건드리지 않는다. 난이도와 판정은 지금과 똑같다.

시안: `.superpowers/brainstorm/18765-1790557218/content/` 의 `direction.html`(A 선택),
`world-design-v2.html`(1부), `ui-design-v2.html`(2부).

## 1부 — 3D 세상

좌표·치수 규칙은 `2026-09-27-three-3d-renderer-design.md` 그대로다. 달라지는 것만 적는다.

### 하늘·빛·안개

- **하늘**: `skyTop → skyMid → skyHorizon` 그라디언트 텍스처 (지금 함수 그대로, 색만 바뀜)
- **안개**: 색 `skyHorizon`, 거리 30 → 95 그대로. 먼 장애물이 하늘빛으로 서서히 드러난다
- **빛**: 반구광(위 하늘색, 아래 잔디색) + 해(흰색, 지금 위치). 세기는 화면을 보며 맞춘다

### 바닥과 선로

- **바닥**: 잔디색 평면
- **선로**: 세 레인을 덮는 자갈색 평면 하나에 **침목 무늬 캔버스 텍스처**를 반복해 입힌다.
  흐르는 느낌은 지금 격자처럼 거리만큼 옮겨서 낸다 — 이번엔 텍스처의 `offset.y` 를 `distance / 침목 간격` 으로 옮긴다.
  네온 격자(`GridHelper`)와 청록 레인 경계선은 지운다
- **레일**: 레인마다 은색 가는 상자 2줄(모두 6줄). 모양이 z 방향으로 같아서 움직이지 않아도 된다

### 건물

- 지금의 고정 시드 배치·흐름(`CITY_SPAN`, `scroll`)을 그대로 쓴다
- 모양: 건물 색 상자 + 흰 창문 무늬 텍스처 + 지붕 테두리(조금 넓고 얇은 어두운 상자). 네온 모서리선은 지운다
- 창문은 건물 크기에 맞춰 반복 횟수를 정해 늘어나 보이지 않게 한다

### 장애물·코인

높이는 판정과 묶여 있어 그대로 둔다. 폭과 깊이는 보이는 모습만 정한다
(충돌은 레인이 같고 z 가 러너를 지나는 한 순간에만 본다).

| 물체 | 뜻 | 새 모양 | 치수 변화 |
|---|---|---|---|
| 바리케이드 | 점프 | 빨강·흰 사선 줄무늬 상자 + 윗면 흰 띠 | 그대로 (1.7 × 1.1 × 0.35) |
| 문(빔) | 숙이기 | 파란 기둥 2개 + 노란 가로판, 앞뒤 면에 남색 ▼ | 그대로 (아래 끝 1.2) |
| 기둥 → **전철** | 레인 바꾸기 | 빨간 전철 앞머리: 몸통 + 윗부분 밝은 띠 + 하늘색 창 + 전조등 2개 | 폭 0.85 → 2.0, 높이 4 → 3.2, 깊이 0.85 → 1.2 |
| 코인 | 먹기 | 금색 원반 + 진한 테두리, 회전은 그대로 | 그대로 |

전철 깊이를 1.2 로 짧게 두는 이유: 길게 만들면 판정이 끝난 뒤에도 몸통이 레인에 남아,
옆 레인에서 들어올 때 전철을 뚫고 지나가는 것처럼 보인다.
높이 3.2 는 점프 꼭대기(발 2.2 + 키 1.8)보다 낮지만, 폭이 레인을 거의 채워 "못 지나간다" 로 읽힌다.
전철은 원래 뛰어넘는 물체로 보이지 않는다.

### 러너

관절 구조와 동작(달리기·점프·슬라이드)은 그대로. 재질만 부위별로 나눈다.

- 머리·팔: skin, 모자: yellow (머리 위 납작한 반구)
- 몸통: pink, 다리: blue
- 왼쪽 팔다리는 지금처럼 한 톤 어둡게 해 앞뒤가 읽히게 한다

### 점수판(`drawHud`)과 비네트

- 점수·속도 단계·코인을 **흰 둥근 카드 하나** 위에 그린다(자리는 지금처럼 왼쪽 위). 카드 아래에 남색 반투명 두께 그림자
- 글자 ink, 보조 글자 inkDim, 속도 막대 yellow(빈 칸은 line), 코인 아이콘 yellow
- 비네트(빨라질수록 가장자리가 어두워짐): 색을 ink 로, 가장 진할 때의 불투명도를 0.75 → 0.4 로 낮춘다

## 2부 — 메뉴 화면

구조(HTML)·문구·순서는 그대로. CSS 만 바꾼다.

- **덮개(`.screen`)**: 어두운 남색 → 밝은 하늘빛 반투명 + 흐림. 뒤의 게임 세상이 비친다
- **카드(`.panel`)**: 흰 바탕, 둥근 모서리 24px, 아래로 두툼한 남색 반투명 그림자("스티커")
- **제목(`.title`)**: Black Han Sans, 노란 글씨 + 남색 테두리 + 아래로 떨어진 남색 그림자. 네온 글로우는 지운다
- **버튼**: 노란 바탕, 진한 갈색 글씨, 아래 yellowDark 두께. 누르면 두께만큼 내려간다
- **입력칸**: 연한 회청 바탕, `line` 테두리 3px, 포커스 때 테두리 ink
- **키 모양(`.cap`)**: 흰 바탕, 아래 테두리가 두꺼운 키보드 모양
- **랭킹**: 1·2·3 등은 금·은·동 동그라미 메달, 나머지는 숫자. 줄 사이 점선
- **준비 화면**: 안내 문구와 카운트 숫자는 흰 글씨 + 남색 테두리, 링은 yellow. 카메라 미리보기 테두리는 흰색
- **게임 오버**: 점수는 흰 글씨 + 남색 테두리 + 그림자, 상태 점은 green / stripeRed, 되돌아가기 막대 yellow
- **경고 배너**: 흰 바탕 + 빨간 테두리 알약. **토스트**: 흰 바탕 + ink 글씨
- `color-scheme` 은 `light` 로. 선택 영역·포커스 테두리도 새 팔레트로
- 움직임 줄이기 설정(`prefers-reduced-motion`) 처리는 그대로 유지

## 확인 방법

1. `npm test` — 서버 쪽 테스트. 이번 변경과 무관하지만 망가지지 않았는지 본다
2. `?test=1` 셀프 테스트 — 헤드리스 방식으로 돌려 전부 통과하는지 본다
3. 브라우저에서 직접 보기(스크린샷)
   - 시작 화면, 준비 화면, 게임 중, 게임 오버가 시안과 같은 분위기인지
   - 키보드로 한 판 하며 바리케이드·문·전철이 멀리서부터 뜻이 읽히는지, 전철을 뚫고 지나가 보이지 않는지
   - 콘솔에 오류가 없는지, 3D 를 못 불러오면 여전히 시작 버튼이 막히는지
4. 코드에 옛 색 이름(`cyan`, `violet`, `ember` 등)과 `bloom` 이 남지 않았는지 검색

## 하지 않는 것

- 3D 모델 파일, 새 라이브러리, 새 파일
- 장애물 높이·판정·난이도 변경
- 어두운 모드 대응 (행사장 전용 밝은 화면 하나로 간다)
- 디버그 패널, 카메라 준비 화면 그림, 관리자 페이지 모양 변경
