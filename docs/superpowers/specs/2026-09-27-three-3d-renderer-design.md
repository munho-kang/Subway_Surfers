# 진짜 3D 화면으로 바꾸기 설계

작성일 2026-09-27

## 개요

지금 화면은 Canvas 2D 에 원근을 흉내 내 그린다(`project()` 로 z 를 화면 y 와 크기로 바꾼다).
이것을 Three.js 로 만든 진짜 3D 장면으로 바꾼다. 네온 사이버 느낌은 그대로 둔다.

**바꾸는 것은 그리는 쪽뿐이다.** 스폰 규칙, 충돌 판정, 속도, 점수, 포즈 인식, 키보드, 준비 화면,
랭킹, 관리자 페이지는 건드리지 않는다. 난이도와 판정이 지금과 똑같아야 한다.

## 확정된 결정

| 항목 | 결정 |
|---|---|
| 엔진 | Three.js 0.186.1, jsDelivr CDN. 빌드 도구 없음 |
| 불러오는 방법 | `<script type="importmap">` 로 `three`, `three/addons/` 를 CDN 에 연결하고 `boot()` 안에서 동적 `import()` |
| 모델 파일 | 없음. 전부 기본 도형(상자·캡슐·원기둥·구)으로 만든다 |
| 카메라 | 러너 등 뒤 위에서 따라가는 원근 카메라. 레인 이동은 절반만 따라간다 |
| 발광 | UnrealBloomPass. `?bloom=0` 이면 끈다 |
| 점수판 | 3D 캔버스 위에 투명 2D 캔버스(`#hud`)를 얹고 지금 `drawHud` 를 그대로 쓴다 |
| 실패 시 | 3D 를 못 불러오면 시작 버튼을 막고 안내 문구를 띄운다. 2D 예비 화면은 두지 않는다 |
| 파일 | 지금처럼 `public/index.html` 하나 |

동적 `import()` 를 쓰는 이유: 정적 import 가 CDN 에서 실패하면 스크립트 전체가 죽어 `?test=1` 셀프 테스트도
못 돈다. 동적으로 부르면 테스트 모드는 Three.js 를 아예 부르지 않는다.

## 좌표 — 게임 값을 3D 세계로

게임 로직의 값은 그대로 쓰고 그리는 순간에만 바꾼다.

- 세계 x = `(lane - 1) * LANE_W`, `LANE_W = 2.4`
- 세계 z = `-o.z` (게임 z 는 멀수록 크다. 카메라는 -z 를 본다). 게임 z 1 = 세계 1 단위
- 러너는 세계 z = `-Z_CHAR` 에 선다. 스폰은 z = -100, 안개가 그 앞에서 가린다

크기는 지금 그림의 비율(러너 키 70 기준)을 세계 단위로 옮긴다. 러너 키를 1.8 로 잡는다.

| 물체 | 모양 | 크기(폭 × 높이 × 깊이) | 판정과 맞아야 하는 것 |
|---|---|---|---|
| 러너 | 머리 구 + 몸통 캡슐 + 팔다리 캡슐 4개 | 키 1.8 | — |
| 바리케이드 | 줄무늬 상자 + 윗면 밝은 띠 | 1.7 × 1.1 × 0.35 | 점프 높이(2.2)보다 확실히 낮다 |
| 빔 | 떠 있는 막대 + 가는 기둥 2개, 아래 모서리 청록 발광 | 1.7 × 0.75, 아래 끝 높이 1.2 | 선 키(1.8)보다 낮고 슬라이드 높이(약 0.7)보다 높다 |
| 기둥 | 보라 상자 + 발광 모서리선 | 0.85 × 4 × 0.85 | 넘을 수 없어 보인다 |
| 코인 | 금색 원반, y 축으로 회전 | 지름 0.7, 높이 1.5 | — |

## 러너 동작

도형을 관절(Group)에 매달아 돌린다. 위상은 지금처럼 `distance * 0.55`.

- **달리기**: 다리는 엉덩이에서, 팔은 어깨에서 `sin(위상)` 으로 앞뒤로 흔든다. 팔다리는 반대로
- **점프**: 무릎을 접고 팔을 든다. 높이는 `sin(t·π) × 2.2`, `t` 는 점프 진행률(0→1)
- **슬라이드**: 몸 전체를 발을 축으로 뒤로 약 70° 눕힌다. 머리 높이가 0.7 근처로 내려와 빔 밑을 지나가 보인다
- 러너 밑 동그란 그림자는 뜰수록 작고 흐려진다

## 배경

- **하늘**: 위에서 아래로 `skyTop → skyMid → skyHorizon` 그라디언트 텍스처를 `scene.background` 로
- **안개**: 색 `skyHorizon`, 30 에서 시작해 95 에서 완전히 가린다. 장애물이 멀리서 갑자기 나타나지 않는다
- **바닥**: 어두운 평면 + 네온 격자. 격자 묶음의 z 를 `distance % 칸 크기` 로 옮겨 흐르게 한다
- **레인 선**: 레인 경계 4줄을 얇은 발광 막대로. 바깥 두 줄은 밝게, 안쪽은 흐리게(지금과 같다)
- **빌딩**: 트랙 양옆에 상자 약 40개. 모양은 고정 시드(`mulberry32(7)`)로 한 번 만들고, 발광 모서리선을 둘러
  네온 도시로 보이게 한다. 카메라 뒤로 지나가면 맨 앞으로 되돌린다
- **빛**: 반구광(위 보라, 아래 청록) + 방향광 하나. 그림자 맵은 쓰지 않는다(무겁다). 물체마다 바닥 그림자 원반

## 속도 표현

지금처럼 빨라질수록 가장자리가 어두워진다(`DARK_SPEED` 까지). 비네트는 `#hud` 캔버스에 그린다.

## 코드 구조

`createGame` 이 상태 굴리기와 그리기를 둘 다 하던 것을 둘로 나눈다.

1. **`createGame()`** — `reset`, `step`, `getState`, `getScore` 는 그대로. 캔버스를 받지 않는다.
   그리기에 필요한 값을 한 번에 넘기는 `view()` 를 추가한다:
   `{ objects, laneVisual, jumpT, sliding, distance, speed, coins, score, nowMs }`
   (`jumpT` 는 점프 중이면 0→1, 아니면 `null`)
2. **`createRenderer3D(THREE, addons, canvas, hudCanvas)`** — `render(view, W, H)`, `renderIdle(atMs, W, H)`, `resize(W, H)`
3. **`drawHud(ctx, view, W, H)`**, 비네트 — 지금 코드를 2D 컨텍스트만 인자로 받게 옮긴다

장애물 메시는 게임 물체와 1:1 로 짝짓는다. 매 프레임 `syncMeshes(map, objects, acquire, release)` 가
새 물체에는 종류별 풀에서 메시를 꺼내 주고, 사라진 물체의 메시는 풀로 돌려준다. 지오메트리와 재질은 종류별로
하나씩만 만들어 공유한다. 새로 만드는 것은 메시 껍데기뿐이다.

없어지는 것: `project`, `laneScreenX`, `LANE_SPREAD`, `PERSPECTIVE_K`, `HORIZON_RATIO`, `WORLD_SCALE`,
`SKYLINE`, `grads`(비네트만 남긴다), `drawWorld`, `groundShadow`, `drawObject`, `limb`, `drawRunner`, `drawCharacter`.

## 성능

MediaPipe 포즈 추적이 이미 GPU 를 쓴다. 그래서:

- 렌더 픽셀 비율 상한 1.5
- 그림자 맵 없음, 광원 두 개
- 블룸은 절반 해상도. 느리면 `?bloom=0`
- 풀링으로 프레임마다 메시를 만들지 않는다

## 오류 처리

- CDN 이나 WebGL 이 실패하면: 시작 버튼 비활성화 + "3D 화면을 불러오지 못했습니다. 새로고침하거나 다른 브라우저로 열어 주세요"
- Three.js 를 불러오는 동안에도 시작 화면과 랭킹은 보인다(3D 장면만 늦게 나타난다)

## 테스트

1. `npm test` — 서버 테스트. 바뀌지 않아야 한다
2. `?test=1` 셀프 테스트(노드 shim 으로 돌린다) — 기존 테스트 전부 통과해야 한다. 게임 로직을 안 건드렸다는 증거다
3. 새 셀프 테스트 1개: `syncMeshes` 가 사라진 물체의 메시를 풀로 돌려주고 새 물체에 재사용하는지
4. 브라우저 확인(`npm run dev`, 크롬): 시작 화면 배경, 키보드로 레인 이동·점프·슬라이드, 각 장애물 모양,
   코인 먹기, 게임오버, 콘솔 오류 없음, `?bloom=0`
