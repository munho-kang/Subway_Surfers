# 점프를 머리 기준으로 — 설계

날짜: 2026-07-15
대상: `game/templates/index.html` 의 `InputMapper`, 디버그 패널, 프리뷰 오버레이, 셀프 테스트

## 배경

점프가 잘 안 걸린다. 사용자는 슬라이드처럼 머리 기준으로 바꾸기를 원한다.

### 진짜 원인은 랜드마크가 아니라 임계다

점프에서 발목은 **몸이 뜬 양 + 무릎을 접은 양** 만큼 올라가고, 머리는 **몸이 뜬 양** 만큼만
올라간다. 그래서 항상 `머리 상승량 ≤ 발목 상승량` 이다. 유일한 실측인 발목 봉우리 0.13 에
대해 머리 봉우리는 0.13 이하였을 것이다. 현재 임계 0.2 는 그 봉우리보다 높으므로 **점프는
지금 한 번도 발화하지 않는다**. 머리로 바꾸기만 하면 오히려 더 안 걸린다.

랜드마크 교체가 무의미하다는 뜻은 아니다. 발목은 **양발 중점** 이라 한 발만 들면 절반만
움직인다 — 실측 0.13 이 비정상적으로 낮았던 유력한 이유다. 머리에는 그 아티팩트가 없다.
머리가 더 정직한 신호다. 다만 임계가 훨씬 낮아야 한다.

**결론.** 랜드마크를 머리로 옮기고, 임계를 실측으로 다시 잡는다. 임계 재측정이 실제 수정이다.

## 설계

### 1. 판정축을 하나로 통일한다

점프를 눈으로 옮기면 두 신호가 같은 값의 부호만 다른 것이 된다.

```
jumpAmount  = (baseline.eyeY - eye.y) / torsoLen   // 머리가 뜨면 양수
slideAmount = (eye.y - baseline.eyeY) / torsoLen   // 머리가 내려가면 양수
              → slideAmount === -jumpAmount, 항상
```

따라서 `headRise` 하나만 계산한다.

- 점프는 `headRise > jumpThreshold`
- 슬라이드는 `headRise < -slideThreshold` (해제는 `-slideThreshold * slideRelease`)

기준선은 `eyeY` 하나만 남는다. `baseline.ankleY` 와 그 캘리브레이션은 사라진다.

`headRise` 에 EMA 를 걸지 않는 것은 기존 발목과 같은 이유다. 점프는 짧고 빠른 순간
신호라 스무딩하면 봉우리가 뭉개진다. 이 주석은 랜드마크만 바꿔 유지한다.

### 2. `!sliding` 가드는 도달 불가능해지므로 삭제한다

축이 하나가 되면 "숙인 채로는 뛸 수 없다" 가드는 구조적으로 죽는다. 슬라이드 중이면
`headRise ≤ -slideThreshold * slideRelease` 이고 점프는 `headRise > jumpThreshold` 를
요구한다. 두 임계가 모두 양수인 한 동시에 참일 수 없다.

기존 테스트 `숙이고 있는 동안에는 점프가 발화하지 않는다` 는 `eyeY: 0.26`(숙임) 과
`ankleY: 0.83`(발목 뜸) 을 **동시에** 만들어 검증한다. 랜드마크가 둘이라서 가능했던
조합이고, 하나가 되면 만들 수 없다.

가드와 테스트를 함께 삭제한다. 남기면 절대 실패할 수 없는 초록 테스트가 되는데, 그건
없는 것보다 나쁘다.

### 3. 발목 경로 전면 제거

점프가 눈을 쓰면 발목은 아무데서도 안 쓰인다. 제거 지점.

| 위치 | 대상 |
|---|---|
| `LM` | `ANK_L`, `ANK_R` |
| `poseMetrics` | `ankle` |
| `DEFAULT_CFG` | `visibilityMin` |
| 캘리브레이션 | `calibSamples` 의 `ankleY`, `baseline.ankleY` |
| `update` | `ankleVisibility`, `ankleOk`, 점프 조건의 게이트 |
| 신호 | `warning: '발이 화면에 보이지 않습니다'` → `warning: null` |
| `debug` | `ankleVisibility`, `baselineAnkleY` |
| `TUNABLES` | `visibilityMin` 슬라이더 |
| 디버그 패널 | `발목 vis` 행과 그 갱신 코드 |
| `makePose` | `ankleY`, `ankleVisibility` 인자 |
| 셀프 테스트 | `발목 visibility가 낮으면 점프가 발화하지 않는다` |

`warning` 필드 자체는 남는다. `hold()` 의 `포즈를 찾을 수 없습니다` / `캘리브레이션
전입니다` 가 계속 쓰고 배너(`showBanner`)가 소비한다. 사라지는 것은 visibility 경고뿐이다.

**관찰 (고치지 않는다).** 슬라이드는 원래부터 눈에 visibility 게이트가 없다. 머리가
화면 밖이면 MediaPipe 가 추정한 엉뚱한 `eye.y` 를 그대로 믿는다. 잠재적 결함일 수 있으나
이번 요청 범위 밖이고, 게이트를 점프에만 붙이면 슬라이드와 비대칭이 된다. 기록만 남긴다.

### 4. 오버레이 — 세 선이 한 기준선에서 뻗는다

점프선의 기준이 `baselineAnkleY` 에서 `baselineEyeY` 로 바뀐다.

```
hline(d.baselineEyeY - cfg.jumpThreshold * d.torsoLen, ...)   // 점프 — 위로
hline(d.baselineEyeY + cfg.slideThreshold * d.torsoLen, ...)  // 슬라이드 — 아래로
hline(d.baselineEyeY + cfg.slideThreshold * cfg.slideRelease * d.torsoLen, ...)  // 해제
```

이제 점프·슬라이드·해제가 모두 눈 기준선에서 위아래로 뻗어, 화면이 판정 구조를 그대로
보여준다. 기존의 "라벨이 겹칠 수 있는 짝은 반대쪽 끝에 둔다" 규칙은 그대로 둔다. 점프선은
기준선 위, 슬라이드/해제는 아래라 점프선이 그 둘과 겹칠 일은 없다.

### 5. 봉우리 기록 — 측정 도구

임계 추측이 두 번 다 빗나간 진짜 이유는 봉우리가 2~3 프레임짜리라 실시간 숫자로는 읽을 수
없다는 것이다. 디버그 패널에 peak-hold 한 줄을 넣는다.

- `peakHeadRise = Math.max(peakHeadRise, headRise)` 를 매 프레임 갱신
- `commitCalibration()` 에서 0 으로 리셋
- 디버그 패널에 `점프 봉우리` 행으로 표시

리셋이 캘리브레이션 시점인 이유는 기준선이 바뀌면 이전 봉우리가 무의미해지기 때문이다.
포즈 글리치로 오염되면 재캘리브레이션으로 씻어낸다.

**측정 절차.** 캘리브레이션 → 두 발로 몇 번 점프 → `점프 봉우리` 읽기 → 그 값의 75~80%
를 임계로 확정.

peak-hold 도 셀프 테스트를 하나 갖는다 — 최댓값을 유지하는가, 캘리브레이션에서 리셋되는가.

### 6. 임계는 잠정값이다

`jumpThreshold: 0.08` 로 두고 **미검증** 임을 주석에 명시한다. 근거는 추정뿐이다 — 발목
봉우리가 0.13 이하였고 머리는 그보다 작다. 높게 잡아 안 걸리는 것(현재 증상)보다 낮게 잡아
오발화하는 편이 낫다. 최소한 파이프라인이 도는 것은 확인된다.

`TUNABLES` 의 `jumpThreshold` 슬라이더 범위 `min: 0.05, max: 0.6` 은 발목 크기를 전제로
잡은 값이다. 머리 상승량은 더 작으므로 `min: 0.02` 로 내린다. 봉우리가 0.05 근처로 나오면
확정값이 0.04 여야 하는데 현재 하한으로는 그 값을 만들 수 없다.

셀프 테스트의 `TEST_CFG` 는 `jumpThreshold: 0.2` 로 못박혀 있어 이 변경에 영향받지 않는다.
합성 포즈는 임계와의 관계로 의미가 정해지므로 실측 튜닝과 분리된다는 기존 결정을 유지한다.

## 셀프 테스트 변경

`makePose` 는 `eyeY` 기본값 0.10, 몸통 0.25 (shoulderY 0.30 / hipY 0.55). `TEST_CFG` 의
`jumpThreshold: 0.2` 는 눈이 `0.2 * 0.25 = 0.05` 이상 올라가야 발화한다는 뜻이다.
`eyeY < 0.05` 가 점프다.

| 테스트 | 변경 |
|---|---|
| `점프 시퀀스에서 jump가 정확히 1회 발화한다` | `ankleY` → `eyeY` 상승으로. `0.06`(0.16 몸통, 아직) → `0.03`(0.28 몸통, 발화) → `0.04`(0.24 몸통, 새 엣지 아님) |
| `불응기 안의 두 번째 점프는 무시된다` | 펄스를 `makePose({ eyeY: 0.03 })` 로 |
| `앞뒤로 움직여 스케일이 변해도 판정이 유지된다` | 먼 사람 몸통 0.125, `eyeY` 기준 0.35 → `0.32` 가 0.24 몸통 |
| `숙이고 있는 동안에는 점프가 발화하지 않는다` | **삭제** (2번 참조) |
| `발목 visibility가 낮으면 점프가 발화하지 않는다` | **삭제** (3번 참조) |
| 슬라이드 테스트 3종 (유지·히스테리시스·포즈 유실) | 변경 없다. 이미 `eyeY` 만 쓴다 |

`makePose` 로 `eyeY` 만 올리면 어깨·엉덩이는 그대로라 물리적으로는 목이 늘어난 꼴이지만,
판정이 읽는 값은 `eye.y` 와 `torsoLen` 둘뿐이고 `torsoLen` 은 불변이라 온몸이 뜬 경우와
같은 값이 나온다. 합성 포즈로서 유효하다.

기존 10 개에서 2 개를 삭제해 8 개, 여기에 봉우리 테스트 1 개를 더해 최종 9 개다.
성공 기준은 `?test=1` 에서 **9/9 통과** 다.

## 위험

**웅크림이 슬라이드를 건드릴 수 있다.** 뛰기 전 반동으로 머리가 내려간다. 그게
`slideThreshold`(0.5 몸통 ≈ 25cm) 를 넘으면 슬라이드가 잠깐 걸렸다 풀리고 점프가 나간다.
작은 홉의 반동은 0.2 몸통 정도라 아마 괜찮지만 측정할 때 함께 확인한다. 실제로 나타나면
점프 직전 웅크림을 슬라이드에서 배제하는 별도 설계가 필요하다 — 이번 범위 밖이다.

**조용함 대역이 좁아진다.** 대역은 `min(jumpThreshold, slideThreshold) / 2` 이므로 임계
0.08 이면 0.04(≈2cm) 다. `context-notes.md` 에 적힌 "기준선이 발목을 쫓아 올라가 점프가
점점 안 걸리는" 증상은 사라진다. 반대로 자세가 서서히 흐트러질 때 기준선이 잘 못 따라간다.
서 있는 동안은 문제없을 것이다.
